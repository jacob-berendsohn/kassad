# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [SemVer](https://semver.org/).
Versions come from git tags via MinVer; nothing here is hand-numbered until a tag exists.

## [Unreleased]

### Added
- Repository scaffold: four packages (`Kassad.Abstractions`, `Kassad`, `Kassad.TypeSafe`, `Kassad.AspNetCore`), tests, sample, eval stub, CI and Trusted Publishing release workflow.
- `Kassad.Abstractions`: `IDecisionModel`, Noul/Choice/Score question and answer records, `Verdict`, `StageResult`, `ErrorPolicy`.
- `Kassad`: JSON policy loader with fail-fast validation, `GuardrailEngine` batching one request per stage, `VerdictResolver`, structured logging.
- `Kassad.TypeSafe`: client for `POST /v1/systemone` with retry/backoff on 429/529, typed exceptions, DI registration via `AddTypeSafe()`.
- `Kassad.AspNetCore`: `UseKassadInbound()` middleware, `AddKassadHandler()` for provider `HttpClient`s, problem+json rejections.
- `schemas/kassad-policies.schema.json` for editor validation of policy files.
- `Kassad`: `EvaluationOptions.Budget` caps how long a stage waits on the decision model. When it runs out the model call is cancelled, every policy for the stage resolves through its `on_error` with a reason starting `budget exceeded`, and `StageResult.BudgetExceeded` is set; the caller's own cancellation still propagates as `OperationCanceledException`. Configure it with `AddKassad(..., o => o.Budget = ...)` or bind `EvaluationOptions` from configuration; `VerdictResolver.FromBudgetExceeded` is public alongside `FromError`.
- `Kassad.Abstractions`: `StageResult.BudgetExceeded`.
- `Kassad.Abstractions`: `ToolCallState` and `GroundingState`, the typed states for the two code-only stages. A decision model presents them as `{ user_intent, tool_name, tool_schema, arguments }` and `{ claim, source_passage, source_id }`; those names are the contract policy instructions can refer to.
- `Kassad`: `GuardrailEngineExtensions.EvaluateToolCallAsync` and `EvaluateGroundingAsync` on `IGuardrailEngine`, fixing the stage and the state type together.
- `Kassad.TypeSafe`: `TypeSafeClient` writes the two state records under those field names, embedding `ToolSchemaJson` and `ArgumentsJson` as JSON values (as strings when the text is not valid JSON) and leaving `source_id` out when it is null.
- Sample: `kassad.policies.json` gains two illustrative `tool_call` policies (`tool_call_off_intent`, `tool_call_effect`) and two `grounding` policies (`claim_unsupported`, `grounding_strength`).
- `Kassad`: `GuardrailEngine` emits OpenTelemetry-compatible traces and metrics through `System.Diagnostics`, with no OpenTelemetry package dependency: one `Kassad.Evaluate` activity per `EvaluateAsync` on the `Kassad` `ActivitySource`, tagged `kassad.stage`, `kassad.model`, `kassad.outcome` and `kassad.had_error`; on the `Kassad` `Meter`, a `kassad.verdicts` counter with one increment per verdict (tags `kassad.stage`, `kassad.policy_id`, `kassad.action`, `kassad.from_error`) and a `kassad.model.latency` histogram of the model call in milliseconds (tags `kassad.stage`, `kassad.model`, `kassad.had_error`). `KassadTelemetry` holds the names as constants for `AddSource` / `AddMeter`. `Docs/specs/telemetry.md` is the spec.
- `Kassad.AspNetCore`: `IStateExtractor` and `KassadOptions.StateExtractor` decide what the policies judge. The default, `DefaultStateExtractor`, reduces an OpenAI chat-completions or Anthropic messages request to an `InboundState` (`user_message`, the last user turn's text, and `system_prompt`) and a response to the assistant's reply, and evaluates any other body whole; `OpenAIChatCompletionsExtractor` and `AnthropicMessagesExtractor` read one provider's shape each, and `RawBodyExtractor` evaluates every body whole. `Docs/specs/state-extraction.md` is the spec.
- Sample: a `ChatRequestStateExtractor` turns the endpoint's `{"message": "..."}` into the same `InboundState`, so the inbound policies see `user_message` for the README prompts too.
- Sample: `Llm:Provider` selects who answers `/chat`. `echo` (the default) answers itself, so only the inbound middleware runs; `openai` forwards the message to OpenAI chat completions through the `llm` `HttpClient` that carries the Kassad handler, so the prompt is screened once more on its way out and the completion on its way back, and needs `OPENAI_API_KEY` (`Llm:Model` picks the model, `gpt-4o-mini` by default). The response body now reports `provider`, `kassad.inbound` (the middleware's verdicts, previously the top-level `kassad` fields) and `kassad.outbound.outcome` (the `Kassad-Outcome` header the handler put on the provider's response; `null` in echo mode). A completion the handler blocks reaches the caller as the handler's own 403; a provider error comes back as a 502 with the provider's answer inside.

### Changed
- `Kassad.TypeSafe`: HTTP 400 responses now raise `TypeSafeRequestException` (previously the base `TypeSafeException`), the same as 422. The API returns 400 for semantic validation failures such as an unknown model or a question with neither instructions nor criteria; neither status is retried.
- `Kassad`: the `GuardrailEngine` constructor takes an `IOptions<EvaluationOptions>?` ahead of the optional logger, so a logger passed positionally must now be named (`logger: ...`). `Kassad` depends on `Microsoft.Extensions.Options`.
- `Kassad.AspNetCore`: the handler forwards requests and returns allowed responses from the exact bytes it read, under every content header the original carried. An allowed response used to come back as a `StringContent` re-encoded from the decoded text with only `Content-Type` copied, so any other content header the provider sent (`Content-Language`, `Content-Disposition`, `Expires`, ...) was dropped and an invalid UTF-8 sequence was rewritten; a request body was buffered whole before being sent.
- `Kassad.AspNetCore`: `UseKassadInbound()` and `AddKassadHandler()` no longer hand the engine the raw body of an OpenAI or Anthropic chat request; inbound policies see `{ user_message, system_prompt }` and outbound policies `{ user_message, system_prompt, completion }` instead. `KassadDelegatingHandler.OutboundState` gained `UserMessage`, `SystemPrompt` and `Completion`; `Response` is now nullable, `Request` and `Response` are `null` when the extracted fields carry that body, and a null field is left out of the serialized state (a request without a text body no longer writes `"request": null`). Set `StateExtractor = RawBodyExtractor.Instance` for the previous behavior.

### Fixed
- `Kassad`: `PolicySet.FromJson` and `PolicySet.FromFile` now throw `PolicyValidationException` for every malformed document. An `actions` entry without an `action` (or set to `null`), a `null` entry in `policies`, a non-string `true`/`false` in noul `criteria`, or a non-string level in score `criteria` used to escape as `InvalidOperationException` or `NullReferenceException` after the error had already been recorded. A non-string choice description was silently read as `null` and a `null` score level as an empty string; both are now rejected, as the spec and schema already required.
- `Kassad.AspNetCore`: rejections from `UseKassadInbound()` now carry `Content-Type: application/problem+json`, as `Docs/specs/rejection-response.md` states. The two-argument `WriteAsJsonAsync` overload had been resetting the header to `application/json; charset=utf-8` after the middleware set it, so every 403 and 413 went out as plain JSON.
- `Kassad.AspNetCore`: `OversizedBodyBehavior = FailOpen` now works in the `AddKassadHandler()` handler. A body is read up to `MaxBodyBytes` plus one byte; one that turns out larger is passed through unevaluated with a warning, the bytes already read ahead of the rest of the stream, where the handler used to buffer the whole body and then throw `InvalidOperationException`. `FailClosed` still answers 413, now without reading past that one byte.
